## Concepts in plain English

### Docker
- **Image** = a recipe (an app + everything it needs). **Container** = a dish cooked from it (a running copy).
- **Port** = a numbered "door" a program listens on. `"5432:5432"` = my laptop's port → the container's port.
- **Volume** = storage outside the container, so data survives when containers are removed.
- **Healthcheck** = Docker keeps asking "are you ready?".
- Run `services:down` when done: containers use RAM/battery even when VS Code is closed.
- ⚠️ Never run `docker compose down -v` by accident (`-v` deletes the database data).

### Git internals
- **Commits store the data.** They're permanent snapshots, saved in `.git/objects`.
- **A branch is just a pointer** (a 41-byte file holding one commit ID). Like a bookmark.
- **HEAD** points to the branch I'm on ("you are here").
- **Each commit points to its parent**, so git can walk back through all history.
- **Old commits are never lost.** e.g. `git show aa7861f:hello.txt` still shows the deleted file.
- **Only committed work is saved.** Ignored files (`.env`, `node_modules`) and Docker data are not in git.
- **Fast-forward merge** = just slide the branch pointer forward (nothing to combine).
- **Merge commit** = a commit with *two* parents, made when joining two lines of work (GitHub PRs do this).
- Deleting a merged branch is safe: it only removes the pointer, not the commits.

### Push, pull, CI
- **push** = laptop → GitHub. **pull** = GitHub → laptop.
- **CI (Continuous Integration)** = a robot that checks every push/PR on a fresh computer and shows ✅/❌.
- **Pull Request (PR)** = a GitHub page asking to merge a branch into `main`, with review + CI checks.

### The team workflow (used for every feature)
branch → commit → push → open PR → CI checks → merge → `git pull` on main → delete branch

### Servers
- **Route** = an address on the server + the code that answers it (`app.get("/health", ...)`).
- **"Cannot GET /x"** = the server works, but there's no route at that address.
- **Status codes**: `200` OK, `404` not found (later: `201` created, `400` bad data, `500` server error).
- `import { config } from "./config.js"` uses `.js` even though the file is `.ts` (Node's module rules).

### `.env` vs `.env.example`
| File           | Holds                    | On GitHub? |
| -------------- | ------------------------ | ---------- |
| `.env`         | Real values + secrets    | ❌ Never    |
| `.env.example` | Setting names, no secrets | ✅ Yes      |
- Real keys go **only** in `.env`. Check the VS Code tab name before pasting a secret.
- New setting? Add it to both files (real value in `.env`, blank in `.env.example`).
- `.env` doesn't move to a new computer with git, so keep real keys in a password manager.

## Commands learned

```bash
npm run services:up            # start Postgres + Redis (Docker Desktop must be running)
npm run services:down          # stop them (data kept)
npm run dev -w @replay/api     # start the API, restarts on save (Ctrl+C to stop)
npm run typecheck -w @replay/api
git switch -c <branch>         # make a new branch and move to it
git switch main                # go back to main
git pull                       # get new commits from GitHub
git log --oneline --graph      # history as a picture
git show <commit>:<file>       # see a file as it was in an old commit
```
