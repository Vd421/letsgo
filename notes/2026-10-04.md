## Lesson 1: what a web page is made of

| Language         | Job                          | Like a house…            | In the shop             |
| ---------------- | ---------------------------- | ------------------------ | ----------------------- |
| **HTML**         | What's on the page           | Walls and rooms          | `index.html`            |
| **CSS**          | How it looks                 | Paint and furniture      | `src/style.css`         |
| **JavaScript/TS**| What it does                 | Electricity and plumbing | `src/main.ts`           |

- An HTML **tag/element** is a box: `<button id="checkout">Checkout</button>`. The `id` is a name tag code can find.
- CSS: `button { background: #2f6fed; }` = "make every button blue". Before `{` = which elements, inside = how.
- Every interactive site does: **find an element → wait for something to happen → change the page.**

### Frontend vs backend

| | Frontend | Backend |
|---|---|---|
| What | What you see and click | What makes it work behind the scenes |
| Runs on | The visitor's browser | A server |
| Languages | Only HTML, CSS, JavaScript | Any (mine is Python) |
| In Replay | Shop, recorder, dashboard | Python API + Postgres |

They talk with **requests and answers** in JSON. That's why the dashboard can't be written in Python:
browsers only understand HTML, CSS and JavaScript.

## Lesson 2: React

- Without React, I must update the screen by hand every time data changes, and it's easy to forget one.
- With React: **screen = a picture of my data.** I change the data, React redraws the screen.

```tsx
function Counter() {
  const [count, setCount] = useState(0);        // state: remembered data, starts at 0
  return <button onClick={() => setCount(count + 1)}>{count}</button>;
}
```

| Word | Meaning |
|---|---|
| **Component** | A reusable piece of a page: a function that returns what to show |
| **State** (`useState`) | Data a component remembers. Changing it with `set…` redraws the page |
| **JSX** | HTML-looking code inside TypeScript (`.tsx` files) |
| `{count}` | "Put this value here" |
| **`useEffect(…, [])`** | "After the page appears, do this once", e.g. load data from the API |
| **StrictMode** | While developing, React draws everything twice on purpose to expose bugs |

## Lesson 3: the tools

- **Vite**: translates TypeScript to JavaScript, serves the site (shop = 5173, dashboard = 5174), updates instantly on save.
  Two apps can't share one port, like two shops can't share one address.
- **Tailwind**: styling with short labels on the element: `p-4` (padding), `bg-white`, `rounded-lg`, `text-5xl`.
- **npm packages**: ready-made code we install (react, vite, tailwindcss, later rrweb's player).

## Lesson 4: TypeScript types

```ts
export type Session = {
  id: string;
  userAgent: string | null;   // text OR nothing ("|" means "or")
  eventCount: number;
};
```

- TypeScript = JavaScript + labels. It's a **spell-checker for code** that works before anything runs.
- Plain JavaScript works too, but most companies use TypeScript for React work.
- The typo test: `sessions?.[0]?.eventcount` →
  `error TS2551: Property 'eventcount' does not exist on type 'Session'. Did you mean 'eventCount'?`
  JavaScript would have stayed silent and shown a blank.
- `?.` = "only if it exists". The line printed `undefined` first (data not loaded yet), then `2`
  (React redrew when the data arrived), each twice because of StrictMode.

## Lessons

### A replay is not a video
rrweb takes **one full "photo" of the page** (every element written down as data), then records only
**changes**: clicked, typed, appeared, moved. The player rebuilds the page from the photo inside a
mini-browser (an **iframe**) and re-applies every change at the right moment. That's why an old
recording shows Tiny Shop's **old** blue buttons: it's what the page really looked like then.

### Test your rule on real data
The first rage rule ("3 fast clicks on one spot") passed all its made-up tests, but on my real
recordings it flagged the **"4 T-shirts" shopper**, who just added shirts quickly. The cart changed
after every click, so the page *did* react. Fix: only count **dead clicks** (no page change within
0.5 s). Made-up examples only test what you think of; **real data finds what you didn't**.

### Pure functions are easy to test
`analyze(events)` (Python), `computeStats(visits)` and `buildMoments(events)` (TypeScript) take data
in and give an answer out, with no database or screen involved. That's why each one has its own tests.

### New words
| Word | Meaning |
|---|---|
| **Design token** | A named design decision (`accent` = the orange) used everywhere instead of the raw value |
| **Route / React Router** | Which page to show for which address |
| **Outlet** | The part of the layout that changes between pages |
| **Custom hook** | Reusable React logic whose name starts with `use` (`useTheme`, `useSessions`, `useReplayer`) |
| **Dead click** | A click the page didn't react to |
| **Rage click** | 3+ dead clicks on one spot within 2 s |
| **iframe** | A mini-browser inside a page; rrweb rebuilds the recorded page in one |
| **SVG** | A way to draw shapes with coordinates; the Overview chart is hand-drawn SVG |
| **Vitest** | The JavaScript version of pytest |
| **Time zone safe test** | Builds example dates in local time, so it passes on any computer (GitHub's runs on UTC) |

## Things that went wrong (part 2)

| Problem | Lesson |
|---|---|
| The API's auto-reload got stuck again; the old code kept answering | On this laptop, run the API **without** `--reload` and restart it after changes |
| "4 T-shirts" flagged as rage | Rule fixed with the "page didn't react" check (see above) |
| Buttons worked but didn't look clickable | Tailwind resets buttons; one CSS rule brings back the hand cursor everywhere |
| My own 17-minute visit pushed the controls off screen | It was recorded in a **tall, narrow** window (310 × 672). The replay now fits by width **and** height, like a video player |
| "Replay" opened an empty visit | Skip visits with almost no events; hide them in the list |
| A click on the page background was named after the whole page's text | Background clicks are now "an empty part of the page" |
| Chart axis showed 38 and 113 | Pick round gridline steps (0, 30, 60, 90, 120) |
