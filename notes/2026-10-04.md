## Lesson 1: what a web page is made of

| Language         | Job                          | Like a house…            | In the shop             |
| ---------------- | ---------------------------- | ------------------------ | ----------------------- |
| **HTML**         | What's on the page           | Walls and rooms          | `index.html`            |
| **CSS**          | How it looks                 | Paint and furniture      | `src/style.css`         |
| **JavaScript/TS**| What it does                 | Electricity and plumbing | `src/main.ts`           |

- An HTML **tag/element** is a box: `<button id="checkout">Checkout</button>`. The `id` is a name tag code can find.
- CSS: `button { background: #2f6fed; }` = "make every button blue". Before `{` = which elements, inside = how.
- Every interactive site does: **find an element → wait for something to happen → change the page.**

### Frontend vs backend

| | Frontend | Backend |
|---|---|---|
| What | What you see and click | What makes it work behind the scenes |
| Runs on | The visitor's browser | A server |
| Languages | Only HTML, CSS, JavaScript | Any (mine is Python) |
| In Replay | Shop, recorder, dashboard | Python API + Postgres |

They talk with **requests and answers** in JSON. That's why the dashboard can't be written in Python:
browsers only understand HTML, CSS and JavaScript.

## Lesson 2: React

- Without React, I must update the screen by hand every time data changes, and it's easy to forget one.
- With React: **screen = a picture of my data.** I change the data, React redraws the screen.

```tsx
function Counter() {
  const [count, setCount] = useState(0);        // state: remembered data, starts at 0
  return <button onClick={() => setCount(count + 1)}>{count}</button>;
}
```

| Word | Meaning |
|---|---|
| **Component** | A reusable piece of a page: a function that returns what to show |
| **State** (`useState`) | Data a component remembers. Changing it with `set…` redraws the page |
| **JSX** | HTML-looking code inside TypeScript (`.tsx` files) |
| `{count}` | "Put this value here" |
| **`useEffect(…, [])`** | "After the page appears, do this once", e.g. load data from the API |
| **StrictMode** | While developing, React draws everything twice on purpose to expose bugs |

## Lesson 3: the tools

- **Vite**: translates TypeScript to JavaScript, serves the site (shop = 5173, dashboard = 5174), updates instantly on save.
  Two apps can't share one port, like two shops can't share one address.
- **Tailwind**: styling with short labels on the element: `p-4` (padding), `bg-white`, `rounded-lg`, `text-5xl`.
- **npm packages**: ready-made code we install (react, vite, tailwindcss, later rrweb's player).

## Lesson 4: TypeScript types

```ts
export type Session = {
  id: string;
  userAgent: string | null;   // text OR nothing ("|" means "or")
  eventCount: number;
};
```

- TypeScript = JavaScript + labels. It's a **spell-checker for code** that works before anything runs.
- Plain JavaScript works too, but most companies use TypeScript for React work.
- The typo test: `sessions?.[0]?.eventcount` →
  `error TS2551: Property 'eventcount' does not exist on type 'Session'. Did you mean 'eventCount'?`
  JavaScript would have stayed silent and shown a blank.
- `?.` = "only if it exists". The line printed `undefined` first (data not loaded yet), then `2`
  (React redrew when the data arrived), each twice because of StrictMode.

## Design: how we got to the approved dashboard

A **mockup** is a clickable picture of the app, made before building it. Changing a picture takes minutes;
changing a finished app takes hours. Saved at `docs/design/dashboard-mockup.html`.

| Version | My feedback → change |
|---|---|
| 1 | First idea: Google-style colours, list + replay |
| 2 | "Cool background, better font, not AI-looking" → ghost-cursor background, Funnel fonts, click strips |
| 3 | "Replay page is the worst" → real browser frame, timeline with activity graph, Moments panel |
| 3 | "No background on replay, sync the colours" → plain background, shared colours |
| 4 | Remove the big headline, autoplay the replay |
| 5 | Matched my reference image: near-black, two accents (orange = problems, violet = normal), calm text |
| 6–7 | Stylish shop fonts, then the same fonts on Sessions and Recent visits |
| 8 | Every visit plays its **own** replay (built from each shopper's real steps) |

**Design lessons**
- Colour should **mean** something: orange-red = rage clicks, violet = normal/good.
- "Not flashy": soft white headings, grey labels, no gradient text.
- In the real product, every replay is different automatically: rrweb rebuilds exactly what each visitor did.

## Things that went wrong (and what they teach)

| Problem | Lesson |
|---|---|
| Live API said "Not Found" for a real session | The server's auto-reload got stuck, so the **old version** answered. Clues: FastAPI's generic "Not Found" and `banana` → 404 instead of 422. A clean restart fixed it. |
| Mockup table went blank | Two functions were both called `render`; the second silently replaced the first. **Name clashes** are a classic bug. |
| Both mockup pages showed at once | A missing rule "hidden things stay hidden". Test outside the usual environment too. |
| Claude couldn't merge PRs | A safety rule: merging into `main` is a human decision. Claude opens PRs, I review and click Merge. |
| Claude couldn't change its own permissions | Also by design ("self-modification"). Only I can change those settings, with `/permissions`. |
